# Table II主模型复现指南

本指南针对UNT-STLLM在四个交通任务上的性能复现。所有命令均从本仓库根目录运行，使用同一个已配置的Python解释器。正式实验固定batch=20、250轮和五个种子，不按test结果选择种子或模型。

## 1. 准备环境与资产

推荐Python 3.11、PyTorch 2.5.1（原实验CUDA构建为cu121）、Transformers 4.40.2、NumPy 2.1.2。请使用GPU虚拟环境中的Python，不依赖系统Python。下面将解释器路径作为示例变量，按主机实际环境填写；已有环境可直接复用。

```bash
PY=/hy-tmp/unt-vnext-env/bin/python
"$PY" -c "import torch,transformers,numpy; print(torch.__version__,transformers.__version__,numpy.__version__); print(torch.cuda.is_available(),torch.backends.cudnn.version())"
```

如需新环境，依赖列表为`requirements.txt`。该文件不包含CUDA驱动安装，不自动调整cuDNN加载方式。使用前确认解释器、驱动与PyTorch兼容。

数据由[STLLM+官方仓库](https://github.com/CoArrayLiu/STLLMPlus)提供[共享入口](https://drive.google.com/drive/folders/1iif59LObrPu-QrpL8Y6lWeajbn_gRf7v?usp=drive_link)。保持预处理NPZ文件原样，不重新切分或生成窗口。目录如下。

```text
UNT-STLLM/
  run.py
  data/
    taxi_pick/{train,val,test}.npz
    taxi_drop/{train,val,test}.npz
    bike_pick/{train,val,test}.npz
    bike_drop/{train,val,test}.npz
  models/gpt2-small/
    config.json
    pytorch_model.bin
```

大括号表示三个独立文件。Taxi节点数为266，Bike为250；每个输入为`[B,12,N,3]`，三通道依次为观测值、日内时间编码和星期编码，输出为`[B,12,N,1]`。每项任务train/val/test分别为2606/870/869个窗口。模型不读取邻接矩阵。

已有远程资产时，保留原文件并复制到仓库根目录。以下示例假设本仓库位于`/hy-tmp/UNT-STLLM`，源资产位于`/hy-tmp/UNT`。路径须与实际位置一致，源与目标不能相同。

```bash
cd /hy-tmp/UNT-STLLM
mkdir -p data models/gpt2-small
for task in taxi_pick taxi_drop bike_pick bike_drop; do
  mkdir -p "data/$task"
  cp -an "/hy-tmp/UNT/data/$task/." "data/$task/"
done
cp -an /hy-tmp/UNT/models/gpt2-small/. models/gpt2-small/
"$PY" run.py check
```

GPT2使用命令行复制，不使用软链接，不重复上传权重。`cp -an`不覆盖已有目标，因此必须运行`check`确认目标没有旧文件或截断文件。检查对全部资产校验大小与SHA256，并保存问题清单。`check`包含test文件的字节校验，不计算预测指标；`smoke`不读取test文件。

也可通过`--data-root`和`--model-path`指定数据与本地权重路径；GPT2不会回退到在线下载。

## 2. 短测与正式运行

先在目标主机使用正式batch验证真实模型的前向、反向、优化器更新和验证流程。

```bash
"$PY" -m unittest discover -s tests -v
"$PY" run.py smoke --tasks taxi_pick bike_pick --seeds 2026 --batch-size 20 --device cuda:0 --output results/smoke
```

短测覆盖两种节点规模，各一个训练批次和一个验证批次。短测结果不会进入正式汇总。小显存机器可用`--batch-size 1`完成诊断，但这不验证正式batch；正式训练拒绝batch=20以外的设置。需要CPU诊断时显式指定`--device cpu`。

单台GPU主机顺序运行全部任务和五个固定种子，默认250轮。

```bash
mkdir -p results
nohup "$PY" -u run.py train --device cuda:0 --resume > results/table2_launch.log 2>&1 &
echo "PID=$!"
tail -n 60 -F results/table2_launch.log
```

启动前的资产检查失败会退出，日志会列出全部问题。运行日志标明任务、种子、条件、job序号、epoch、训练损失、当前验证MAE、历史最优、学习率和耗时。超过60秒无输出时有阶段心跳。不要对同一结果目录并发启动多个运行器。

可用`--tasks taxi_pick`或`--seeds 2026`分批执行同一固定协议。需要保持同一个`--output`目录，最终必须收齐四任务全部五个种子。`--print-every 5`可调整epoch日志间隔，心跳仍保留。

## 3. 训练与指标规则

训练scaler只在train输入的观测通道拟合全局均值和总体标准差；时间通道不标准化，标签保持原始计数。尾批重复最后一个窗口补足batch，训练前按固定种子逐轮打乱已填充序列。

语言骨干取GPT2-small前五块，节点注意力为双向访问，最后两块加入softmax前动态关系偏置。预训练骨干参数冻结，最后两块的QKV及输出投影使用rank=8、alpha=16的LoRA；任务编码、融合、变分投影、关系模块和预测头参与训练。

损失为正值标签掩码下的MAE、权重0.024的预测序列幅度谱MAE与KL项。为保持表II的实现，KL先乘编码器尺度0.001，再乘50轮线性退火至0.001的训练尺度，有效上限为`1e-6`。Ranger使用学习率0.003、权重衰减0.0001、梯度中心化、Lookahead与范数裁剪5。

模型按填充后的验证批次MAE的等权均值选优。连续12轮未改善时，回载历史最优模型并将学习率减半，优化器状态继续保留；训练完成250轮。最优模型状态保存在内存中，程序不输出checkpoint。中断后，`--resume`保留已完成单元，未完成单元从第1轮重新开始，旧attempt日志不覆盖。

最终模型由验证集选定后评估test，裁去尾批填充窗口。每个预测步分别计算MAE、RMSE、WAPE，再对12步取均值。指标使用`truth > 0`掩码；单种子JSON及`by_seed.csv`中WAPE为比例，`by_task.csv`和参考表中WAPE为百分数。五种子离散度为样本标准差（ddof=1）。

## 4. 结果、续跑与收集

```bash
"$PY" run.py summary --output results/table2
```

结果组织为`results/table2/<task>/seed_<seed>/attempt_<序号>/`。每个单元保存`protocol.json`、`status.json`、`events.log`、`epochs.json`和成功时的`metrics.json`。状态文件包含阶段、执行命令、耗时、退出码和失败错误尾部。

汇总保存到`results/table2/summaries/<本次时间>/`，包括`summary.json`、`by_seed.csv`和`by_task.csv`。缺失单元不会补值，也不会把短测或不同签名的运行拼成正式结果。`complete`表示本次所选范围齐全，`table2_complete`需要四任务和全部五种子齐全。没有完整五种子时不要将部分汇总当作表II复现。

```bash
tar -czf UNT-STLLM_table2_results.tar.gz results/table2
```

只需收集结果目录。数据、GPT2和模型参数不应包含在结果包或Git提交中。仓库的`.gitignore`默认排除这些资产。
